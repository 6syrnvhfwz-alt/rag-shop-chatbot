# Day 7 · RAG 智能客服：查询改写 + 调优收尾

对应代码：`rag_chatbot_v3.py`（最终版，模型 qwen3:8b）

## 今天解决了什么问题

Day 6 藏着一个 bug：客户追问"那尺码不合适算哪种？"时，**这句话里没有"运费"两个字**，
直接拿去检索会搜到"尺码表"而不是"退换货运费"。Day 6 能答对是靠聊天历史蒙的——
一旦资料没检索到，AI 就开始编（实测"关税"问题就编出了"建议联系当地海关"，资料里根本没有）。

**解法：查询改写（Query Rewriting）**——检索前，先让 AI 把半截话结合上下文补全成完整问题：

```
"那尺码不合适算哪种？"  →  "尺码不合适退换货运费谁承担"  → 再检索，精准命中
```

完整链路变成：**改写 → 检索 → 回答**。

## 词汇表（每个都对应今晚亲眼见过的事故）

| 词汇 | 大白话 | 今晚的例子 |
|---|---|---|
| **查询改写** | 检索前把客户的半截话补全成完整问题 | "那关税呢？" → "商品进口关税由谁承担？" |
| **幻觉** | AI 一本正经地胡说八道，资料里没有也敢编 | "建议联系当地海关"（知识库无此内容） |
| **护栏 / 防御性编程** | 永远不假设 AI 听话，输出必须过一道检查，不合格就拦住 | 改写超 30 字/带句号 = 判定写小作文，拦截 |
| **上下文污染** | 喂给 AI 的历史里"客服"一直在回答问题，改写模型就模仿前辈回答，而不是改写 | 根因：历史以 assistant 角色喂入；解法：历史拼成纯文本塞 user 消息 |
| **温度 temperature** | AI 的"放飞旋钮"：0 死板照做，1 自由发挥。机械活调 0.1 | 改写用 0.1，不许加戏 |
| **Few-shot 给示例** | 别光下命令，直接给一道做好的例题，比十句规则管用 | prompt 里塞"退换货运费→尺码"标准答案 |
| **回退 Fallback** | 新方案失败时的备胎：改写两次都跑偏，就用客户原话检索 | 原话再差也比 AI 编的小作文强 |
| **思考模式 think** | qwen3 默认先吐 `<think>` 内心独白，客服场景浪费，`"think": False` 关掉 | — |

## 今晚的调试方法论（比代码更值钱）

1. **先让问题可见**：护栏拦东西时必须把"尸体"打印出来（它到底输出了啥），
   不能只显示"不合规"——闭着眼没法修 bug。
2. **再定位根因**：看到 AI 两次输出都是完整答案 → 发现是历史记录的角色在"教坏"它。
3. **最后改喂法**：历史从 assistant 角色改成纯文本，模型面前没有"回答者"榜样。
4. **模型决定上限，工程决定下限**：
   - qwen2:7b 面对喂到嘴边的示例都不抄 → 换 qwen3:8b（上限）
   - top_k=4 多捞资料 + 关键词重排 + 护栏回退（下限）
   - 企业里两个都要，面试问"怎么保证 RAG 靠谱"就是这套答题框架。

## 模型备注

- qwen2:7b（2024年6月）→ qwen3:8b（2025年4月），体积差不多（~5GB），指令遵循强一代。
- 删除旧模型：`ollama rm qwen2:7b`；查看列表：`ollama list`。
- **nomic-embed-text 是嵌入模型，不能删**——检索全靠它，和对话模型是两个工种。

## 最终 RAG 全链路

```
知识库切分 → 向量化(nomic-embed) → 混合检索(向量海选6段+关键词重排取4段)
→ 查询改写(温度0.1 + few-shot + 护栏校验 + 重试回退)
→ 带记忆回答(/api/chat + history)
```
